# ESP32 Pocket Control：行動介面設計

## 設計目標

本 App 讓使用者以單手操作的直向手機介面，在同一個 Wi-Fi 區域網路中設定、查看與控制 ESP32-WROOM 裝置。第一版聚焦於一塊 ESP32 的 LED／GPIO 控制與狀態回報，所有控制行為都以可理解的狀態、明確的操作回饋與可追蹤的命令紀錄呈現。Needle 的自然語言解析只保留為未來的命令輸入擴充點，不在第一版內呼叫雲端模型或建立帳號系統。

介面以 **9:16 直向螢幕與單手操作** 為前提，遵循 Apple Human Interface Guidelines：主要操作放在拇指可及的下半部；使用系統樣式的 tab bar、sheet、switch 與大型圓角卡片；不以顏色作為唯一狀態標示，並為成功、離線及錯誤提供文字訊息。

## Screen List

| 畫面 | 主要內容與功能 |
| --- | --- |
| 控制台 | 顯示目前 ESP32 的連線狀態、裝置名稱與位址；提供 LED 開關、亮度滑桿、套用控制及最近一次命令結果。 |
| 裝置設定 | 讓使用者輸入或編輯裝置名稱、區域網路 IP／主機名稱與 HTTP 連接埠；可測試 `/health` 端點並儲存至本機。 |
| 命令紀錄 | 顯示本機保存的控制請求、時間、結果與錯誤原因，支援一鍵清除。 |
| 關於與協定 | 說明 ESP32 應提供的 `/health`、`/state` 與 `/command` 端點，並保留未來 Needle 命令解析的整合說明。 |

## Key User Flows

| 使用者目標 | 操作流程 |
| --- | --- |
| 首次連接裝置 | 開啟 App → 控制台顯示「尚未設定」→ 點擊「設定裝置」→ 輸入名稱與 IP → 測試連線 → 儲存 → 返回控制台。 |
| 控制 LED | 控制台 → 切換 LED 開關或拖曳亮度 → 點擊「套用至 ESP32」→ App 驗證設定與數值 → POST 命令 → 顯示成功／失敗回饋並新增紀錄。 |
| 查看裝置狀態 | 控制台 → 點擊「重新整理狀態」→ GET `/state` → 更新 LED、亮度、連線時間與狀態文字。 |
| 排除連線問題 | 控制台顯示離線 → 點擊「檢查設定」→ 裝置設定 → 測試 `/health` → 顯示 HTTP／網路錯誤及建議。 |
| 回顧指令 | Tab「紀錄」→ 查看最近請求與結果 → 需要時清除本機紀錄。 |

## Color Choices

App 採用偏工控與家庭自動化的「深石墨 + 電光青綠」配色，以提供清晰、可信且可在低光環境閱讀的控制體驗。

| Token | 色彩 | 用途 |
| --- | --- | --- |
| Primary | `#087E8B` | 主要行動、啟用狀態與控制重點。 |
| Background | `#F6F8FA` / `#10181C` | 淺色與深色模式背景。 |
| Surface | `#FFFFFF` / `#162126` | 卡片、底部面板與控制容器。 |
| Foreground | `#102A33` / `#EDF7F8` | 主要文字與數值。 |
| Success | `#16803C` / `#55C985` | 線上、已執行與健康狀態。 |
| Warning | `#A66100` / `#F4B860` | 尚未設定、重新嘗試與待確認。 |
| Error | `#B42318` / `#FF857C` | 離線、HTTP 失敗與拒絕執行。 |

## 資料與安全邊界

裝置設定與命令紀錄僅保存於手機本機。控制命令固定使用 `set_led` 行為與 `on`、`brightness` 欄位；App 會在送出前驗證 `brightness` 為 0 至 255 的整數、裝置 URL 為私有網路位址或使用者明確輸入的主機名稱。第一版不包含雲端帳號、遠端穿透、繼電器、市電或高風險硬體控制。當後續接入 Needle 時，Needle 僅能產生候選的結構化命令，實際網路請求仍須通過本 App 的欄位與風險驗證。
